# AGENTS.md

## Repo Shape
- This is a Flux CD GitOps repo for a Kubernetes homelab; there are no package scripts, app tests, or language build steps at the root.
- `flux/flux-system/gotk-sync.yaml` is generated by Flux and says `DO NOT EDIT`; normal changes should target `cluster/`, `infra/`, or Flux Kustomization wiring files.
- Flux tracks `main` from `https://github.com/kacperjarocki/homelab.git` and bootstraps from `./flux`, whose usable Kustomize entrypoint is `flux/flux-system/`.

## Layout
- `cluster/` contains workloads/apps and has a root `cluster/kustomization.yaml`; adding an app usually requires adding its directory there.
- `infra/` contains controllers and platform components referenced directly by Flux Kustomizations under `flux/flux-system/*.yaml`; many infra leaf dirs intentionally have no `kustomization.yaml`.
- `flux/flux-system/kustomization.yaml` is the list of Flux control-plane and reconciliation resources; add new Flux Kustomization resources there or Flux will not apply them.

## Validation Commands
- Render app/workload manifests with Kubernetes' bundled Kustomize: `kubectl kustomize cluster > /dev/null` or `kubectl kustomize cluster/immich > /dev/null`.
- Render Flux bootstrap manifests with: `kubectl kustomize flux/flux-system > /dev/null`; `kubectl kustomize flux` fails because `flux/` has no root kustomization file.
- Render an infra path without a `kustomization.yaml` through Flux dry-run, for example: `flux build kustomization certmanager-issuer --path ./infra/certmanager/certIssuers --kustomization-file ./flux/flux-system/certmanager-issuer.yaml --dry-run > /dev/null`.
- If a cluster context is available, compare local changes against the live Flux object with: `flux diff kustomization cluster --path ./cluster --local-sources GitRepository/flux-system=./`.

## Flux Dependencies
- Do not rely on YAML list order for reconciliation ordering; use `spec.dependsOn` in `flux/flux-system/*.yaml`.
- Current explicit chains include `kyverno -> policies`, `network-metallb -> network-metallb-config -> traefik`, and `certmanager-helm -> certmanager-issuer -> longhorn-system`.
- `cluster` currently depends on `longhorn-system`; `cnpg` also depends on `longhorn-system`. Add or adjust dependencies if a workload needs a CRD/controller to exist before it reconciles.

## Repo-Specific Gotchas
- Renovate is configured to scan all `*.yaml` files with its Flux manager, so Helm chart/image versions in manifests are update candidates.
- GitVersion releases run only on pushes to `main`; version bumps are driven by Conventional Commit prefixes in `GitVersion.yml` and tags are pushed as `v<MajorMinorPatch>`.
- Some manifests contain secret references, and at least one current Helm values file contains plaintext credentials; avoid pasting full rendered YAML into responses unless necessary.
- Certificates and ingresses use the `homelab.kacperjarocki.dev` / `kacperjarocki.dev` DNS zone and cert-manager ClusterIssuers defined under `infra/certmanager/certIssuers/`.
